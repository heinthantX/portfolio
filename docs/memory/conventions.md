# Conventions

## Motion: no sideways travel
Motion never moves left or right on its own. Use vertical, scale or opacity. The one exception: hero text blocks slide in from the side as they scroll in, and leave back to the same side (`slideFrom` in `SignalHero.tsx`). Intro, wave and finale text rise from below instead. Cursor parallax and user-triggered hover nudges (`translate-x-1` on "→") are allowed. Owner preference, see `docs/design/DECISIONS.md` D8, relaxed for entrance slides by D12.

## Scroll state stays out of React
Scroll progress is read in rAF or `useFrame` and never put in React state, so scrolling causes no re-renders. See `docs/specs/signal-hero.md`.

## Typecheck needs typegen on a fresh checkout
On a fresh checkout run `pnpm exec next typegen` before `pnpm typecheck`. `LayoutProps` is generated by Next and the typecheck depends on it.

## Chapter indices come from CHAPTER_IDS
Derive `CHAPTERS`, `LAYER_OFFSET` and `WAVE_CHAPTER` from `CHAPTER_IDS` in `src/features/signal-scene/timeline.ts`. Never hardcode a chapter index. Layer j is chapter `j + LAYER_OFFSET`, so `j + 1` would land on the wave. See `docs/specs/signal-hero.md`.

## Formation moves are per point
Move the formation by blending each point between its two endpoint world-space poses in the shader (`uMatA`/`uMatB`), each on its own stagger. Do not move a group transform: it shifts every point rigidly, so any side change slides the whole formation. See `docs/design/DECISIONS.md` D9.

## Scroll-linked text uses ScrollWords
Split text with `ScrollWords` (`src/components/site/scroll-words.tsx`), not per-word JS. `view` mode uses CSS view timelines. `driven` mode reads one `--reveal` variable that the frame loop writes, and only when it changes by more than 0.002.
- Match accent words after stripping case and punctuation from both the accent list and the words. Without that, "holds." never matches "holds".
- Blur applies only at ≥768px.
- Do not put `data-reveal` on a wrapper of a ScrollWords block; it double-fades.

See `docs/specs/scroll-words.md`.

## Chapter jumps go through goTo
Every chapter jump (rail, stack outline, layer grid, wheel) calls `goTo` from `useChapterSnap` (`src/features/signal-scene/useChapterSnap.ts`). Never call `lenis.scrollTo` directly for a chapter: a direct call fights the snap and skips the chapter pace (`STEP_S` 2s, `MIN_S` 1s since D15; set them with `NEXT_PUBLIC_CHAPTER_STEP_S` / `NEXT_PUBLIC_CHAPTER_MIN_S`, never by hardcoding). See `docs/specs/signal-hero.md` and `docs/design/DECISIONS.md` D10 and D15.

## Show skill breadth in copy, not in highlights
Do not highlight individual skill tags (no signal-coloured tag for MongoDB or NoSQL). The owner rejected that. Show breadth in the copy instead, e.g. "SQL and NoSQL: Postgres and MySQL for relational data, MongoDB for documents". Write MySQL, not MariaDB (MariaDB is a fork). See `docs/design/DECISIONS.md` D10.

## E2E against the prod server: kill the port first
`next start` keeps serving the old build after a rebuild, so stale chunks load and the canvas never mounts in e2e. Kill the port before restarting the server, then run the tests. Playwright uses `pnpm start` with `reuseExistingServer`, so rebuild before running e2e after any UI change, or the tests hit stale markup.

## Mobile menu is a header dropdown, not a bottom sheet
Below `md` the nav lives behind a hamburger at the far right of the header, in a panel that drops from the top-right. Chosen over a full-screen overlay to keep the page visible behind it. Off-home, a House icon Home link sits in the header beside the hamburger, and Home is also a text link in the panel. The closed panel is `inert`. See `docs/specs/mobile-menu.md`.

## Nav arrow: z-index goes on the svgs, not the wrapper
The desktop nav hover arrow has a lap (back layer only) and a cross through the label. The cross is a moving dash on the front masked layer and its halo, and it leaves no cross at rest, so the text stays readable. The current-page rest arrow (0.35 opacity) keeps its head at rest; the head sits off the label's top-right corner. It retracts while another link is hovered (see "Nav current-page arrow retracts on hover" below). Put the `z-index` on the svgs inside `.nav-shot` (`isolation: isolate`, `z-index: 1` so the head paints over the preview card). A `z-index` on the `.shot-arrow` wrapper creates a stacking context and traps the front layer behind the label. Any `useId` value used in a `url()` must have its colons stripped. The arrow dives into the card's nail hole (`.pv-hole`), so the card is pinned by the arrow itself. Reduced motion disables the card swing and the hole pop. See `docs/specs/nav-hover-preview.md`.

## Nav current-page arrow retracts on hover
While another nav link is hovered, the current page's faint arrow retracts fully: the rest head pops off (0.1s), the line undraws back toward the tail (`stroke-dashoffset` to 1, 0.3s, 0.08s delay), then the tail fades (0.33s delay). On hover end it redraws (line 0.4s after 0.15s, tail 0.2s, rest head at 0.45s). The current page's label colour stays highlighted. The trigger is `nav[data-pinned]` with a 120ms debounce, not `:has(:hover)`, because `:has(:hover)` flickers when the pointer moves between links. The retract block lives in `src/app/globals.css` after `@keyframes shot-fade`. See `docs/specs/nav-hover-preview.md`.

## Reveal targets never use translate-* utilities
Anything the text reveal animates (`data-part`, `data-block`, text targets) must not position itself with `translate-*` utilities. The WAAPI reveal animates the CSS `translate` property with fill both, so it overrides the utility. Use margins (`-ml-[…]`) or a non-animated wrapper. See `docs/memory/fixes.md` (timeline dots).

## Nav arrow state comes from data-hover
The desktop nav arrow and the preview card read one React state. The link gets `data-hover` when `hover.href === item.href`, and every arrow selector uses `.nav-shot[data-hover]` / `:not([data-hover])`. Never style the arrow from CSS `:hover` or `:focus-visible`. The label colour uses `data-hover:text-text`. See `docs/specs/nav-hover-preview.md`.

## Edit globals.css in place
Edit `src/app/globals.css` in place. `sed -i ''` replaces the file's inode, and the Next dev watcher missed it, so it kept serving stale CSS until the file was re-written in place. Use the Edit tool, or write the file contents without replacing the inode.

## Command menu placeholder is a test contract
The command menu input keeps the placeholder "Type a command or search...". The e2e tests rely on it, so change the copy only together with the tests. See `docs/specs/command-menu.md`.
